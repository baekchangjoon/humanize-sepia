# 기술 채널 적용

GitHub PR 본문·Jira 티켓·Confluence 해설서·구현 계획서·사내 기술 블로그·README·커밋 메시지를 쓰거나 다듬을 때 **이 파일 하나만** 읽는다. 공통 기준은 SKILL.md를 따른다. 다른 reference는 사용자가 해당 작업(자소서, 연구계획서, 대안 비교 등)을 요청할 때만 읽는다.

## 분량

- 사용자가 축약을 허용하거나 요청하면 중복·부연·자기평가("정직 기록", "핵심은 ~이다")·재요약 삭제를 필요한 수정으로 본다. **줄이는 대상은 이 네 가지뿐이다.** 아래 [의미 보호](#의미-보호) 문장은 줄이는 대상이 아니다.
- 분량 목표: 허용만 했으면 원문 이하, 비율을 지정했으면 그 비율(예: −30%)을 따른다.
- 축약체(`~함`·`~임`·명사 종결·괄호 부연)를 완결된 문장으로 풀 때는 같은 구간의 중복을 함께 덜어 분량이 원문을 넘지 않게 한다.
- 우선순위는 의미 보호 > [서식](#서식) > 분량 목표다. 분량 목표는 하위 목표다.
  - 원문 이하를 맞추려면 의미 보호 문장을 지우거나 합쳐야 한다면 분량 목표를 포기한다.
  - 표·다이어그램·줄바꿈·끝의 `결론·다음 행동` 섹션을 빼거나 줄여서 분량을 맞추지 않는다.
  - 분량 목표를 넘기면 이유를 한 줄로 보고한다.
- 아스키 다이어그램과 코드 블록은 분량에 넣지 않는다. 점검할 때 `--exclude-fenced`를 붙인다.
- 양괄식 문서 끝의 `결론·다음 행동` 섹션은 줄이는 대상인 재요약으로 보지 않는다.

## 보호 구간

다음은 표기까지 그대로 둔다. 위치·서식(목록↔표)은 바꿀 수 있다.

- 인라인 코드·코드 블록·경로·URL·커밋 해시·명령어·플래그
- REQ-ID·이슈 번호(`#123`, `ABC-123`)·버전·수치와 단위·비교 기준
- 체크박스(`- [ ]`)·상태 기호(🟢🟡🔴🔵)·추적 매트릭스
- 에이전트용 지시 블록(`> **For agentic workers:** …`, `REQUIRED SUB-SKILL`): 저장소에 남는 원본에서는 유지한다. Confluence 게시본처럼 사람이 읽는 사본이라고 사용자가 밝힌 경우에만 뺀다.

## 의미 보호

표기는 바꿀 수 있지만 **내용은 빠짐없이 남긴다.** 다른 문장과 합칠 때도 아래 요소가 결과에 그대로 읽혀야 한다.

- 결정의 근거: "~때문에", "~라서", "이유는", "근거는"으로 이어지는 왜
- 기존 결함·실패 조건: "~해도 통과했다", "~하면 깨진다", 고치기 전 상태 설명
- 주의·경고·부작용: "오히려", "단", "주의", "하지 말 것"
- 용어·기호 정의: "N은 ~", "~를 뜻한다", 약어 풀이
- 범위·대상 한정: "~만", "~에 한해", "이번 범위 밖", 대상 서비스·SUT 지정

점검: 원문에서 위 요소가 들어간 문장마다 결과의 대응 문장을 찾는다. 찾지 못하면 되살린다.

## 말투와 언어

- 기존 문서를 다듬을 때는 원문의 종결체를 따른다. 원문이 섞여 있으면 많이 쓴 쪽으로 맞춘다.
- 새로 쓸 때는 경어체(합니다체)로 쓴다.
- 예외: 코드 블록, 인용, 표 셀 안의 키워드, 단순 나열(명사 종결 개조식)은 종결체를 맞추지 않는다.

| 대상 | 언어 |
|---|---|
| README | 한국어 |
| PR 제목 | 영어 |
| PR 본문 | 한국어 |
| 커밋 메시지 | 영어 |
| Jira·Confluence·계획서·블로그 | 원문 언어, 새로 쓰면 한국어 |

- 어느 언어로 쓰든 코드·식별자·경로·명령어·기술 용어는 원래 표기를 유지한다.
- 영어로 쓰는 PR 제목과 커밋 메시지는 저장소에 이미 있는 관례(Conventional Commits 등)를 따르고, 없으면 명령형 한 줄로 쓴다.

## 채널별 구조

| 채널 | 구조 | 형식 |
|---|---|---|
| GitHub PR 본문 | 요약(무엇·왜 1~3줄) → 변경 사항 → 검증(명령·결과 수치) → 리뷰 포인트·후속 | 개조식 |
| Jira 티켓 | 요약(1~3줄) → 배경 → 문제/요구 → 완료 조건(체크리스트) → 참고 링크 | 개조식 |
| Confluence 해설서 | 결론 → 개념 설명 → 예시·다이어그램 → 한계 | 설명은 짧은 문단 |
| 구현 계획서 | 결론(목표·핵심 결정) → 범위/비목표 → 제약 → 단계(체크박스) → 완료 기준 | 개조식 |
| 사내 기술 블로그·회고 | 결론·요약 → 배경 → 과정 → 수치 결과 → 한계 | 설명은 짧은 문단 |
| README | 한 줄 소개 → 권장 설치 → 사용 예 → 설정 → 기타 경로 | 개조식 + 코드 블록 |

- 원문에 이미 있는 섹션 순서는 독자 이해를 막을 때만 바꾼다. 결론이 뒤에 있으면 앞으로 올린다.
- 모든 글은 결론으로 시작한다(두괄식).
- Confluence 해설서·구현 계획서·사내 기술 블로그·회고는 양괄식으로 쓴다. 글자 수가 아니라 문서 종류로 정한다.
  - 끝에 `결론·다음 행동` 섹션을 둔다.
  - 이 섹션에는 결론을 다시 쓰고, 결정 사항과 다음 행동(누가·무엇을·언제)을 정리한다. 원문에 없는 담당·기한은 지어내지 않고 빈 채로 둔다.
- GitHub PR 본문·Jira 티켓·README·커밋 메시지는 끝 섹션을 두지 않는다.

## 서식

**줄바꿈**
- 한 줄에는 한 문장만 쓴다. 결론·요약 문단도 예외가 아니다. 두 문장 이상이면 목록 항목으로 나눈다.
- 한 문장에는 사실 하나만 담는다. 경로·스펙 링크·리뷰 수처럼 덧붙는 정보는 `라벨: 값` 항목으로 뺀다.
- 괄호 부연은 한 줄에 하나까지 쓴다. 더 있으면 하위 항목으로 내린다.
- 인라인 코드를 뺀 본문이 80자를 넘으면 나눈다.
- 줄은 목록이나 빈 줄로 나눈다. 마크다운은 줄바꿈 하나를 같은 문단으로 이어 붙인다.
- 한 줄에 쉼표나 `·`로 4개 이상 이어 붙인 나열은 목록으로 푼다.

**표**
- 비교 대상이 2개 이상이고 같은 속성을 2개 이상 견주면 목록 대신 표로 쓴다.
- 셀에는 키워드나 한 문장만 넣는다. 설명이 더 필요하면 표 아래 목록으로 푼다.
- 표는 MECE로 만든다.
  - 행끼리 겹치지 않게 분류 기준을 하나만 쓴다.
  - 행을 합치면 다루는 범위 전체가 되게 한다. 남는 경우는 `기타` 행으로 받는다.
  - 열은 모든 행에 같은 뜻으로 채울 수 있는 속성만 둔다. 해당 없는 칸은 비우지 않고 `없음`으로 쓴다.
- 표를 만들려고 원문에 없는 칸 내용을 지어내지 않는다. 채울 근거가 없으면 표 대신 목록으로 쓴다.

**다이어그램**
- 구성 요소가 3개 이상인 아키텍처나 단계가 3개 이상인 흐름은 `text` 코드 블록에 아스키 다이어그램으로 그린다.
- 상자에는 행위자(사람·서비스·시스템)를, 화살표에는 그 행위자가 하는 일(무엇을)을 적는다.

```text
[개발자] --PR 생성--> [GitHub] --웹훅 전달--> [CI] --테스트 결과 댓글--> [GitHub]
```

- 원문에 있는 구성 요소와 관계만 그린다. 그릴 근거가 부족하면 그리지 않는다.
- 다이어그램 아래에 같은 흐름을 한두 줄로 설명한다. 다이어그램만으로 정보를 전하지 않는다.

## Confluence 게시

Confluence에 직접 게시하거나 수정할 때(API·MCP·브라우저 자동화)는 다음을 적용한다.

- 페이지 너비는 항상 최대(full-width)로 둔다. 페이지 속성 `content-appearance-published`와 `content-appearance-draft`를 모두 `full-width`로 설정한다. 생성 요청에 함께 넣으면 적용되지 않을 수 있으므로, 페이지를 만든 뒤 별도 요청으로 설정한다. 속성이 이미 있으면 버전 번호를 올려 갱신한다.
- 표 너비도 최대로 둔다. storage format에서는 `<table data-layout="full-width">`, ADF에서는 table `attrs.layout`을 `full-width`로 쓴다.
- 마크다운만 넘겨주고 게시는 사용자가 할 때는 이 두 설정을 결과 끝에 한 줄로 안내한다.

## 최종 점검

```bash
python3 "${CLAUDE_SKILL_DIR}/scripts/check_preservation.py" <원문> <결과> --max-line 80 [--max-ratio 1.0] [--exclude-fenced]
```

- 종료 코드 1이면 보고된 보호 토큰을 되살리거나 분량을 다시 줄인 뒤 한 번만 재검사한다. 분량을 줄일 때도 [분량](#분량)의 우선순위를 따른다. 서식 때문에 남은 초과는 보고만 한다.
- 서식 변경(표 분할, 코드 표기 분리)으로 생긴 오탐은 원문과 대조해 무시한다.
- `long line`으로 보고된 줄은 [줄바꿈](#서식) 규칙대로 나눈다. 코드·경로 자체가 길어서 나눌 수 없는 줄은 그대로 둔다.
- `mixed_register=True`이면 [말투와 언어](#말투와-언어)의 예외 구간 때문인지 확인하고, 본문 문장이 섞였으면 하나로 맞춘다.
